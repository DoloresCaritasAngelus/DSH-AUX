# 降级链设置页前端设计

> 状态:✅ 活跃
> 最后核实:2026-09-17
> 类型:**设计(未实现)** —— 本文批准后再落代码。
> 范围:仅 `aux.tasks.<task>.models`(降级链)的编辑控件。不含设置页分区重构、`nativeRoutes` 选择器、`/aux models` 能力探测。
> 关系:取代早期 `archive/phase4-ui-2026-09-09` 上的设置页改造。那份实现的**意图正确、落地在人机交互上失败**,原因见 §1。

## 1. 为什么上一版失败(从真人视角复盘)

上一版把「一个多行文本框,一行一条」换成了「页内 8 个折叠区 + 任务摘要行 + 点『编辑』+ 折叠供应商分组 + 目录勾选 + 独立排序面板 + 页脚保存」。自述是「七分区」,自动化 510/510 全绿 —— 但那些测试只钉住了**结构**(默认只展开一个区、点编辑才展开、高级区字段一个不丢),没有一条能判「人能不能完成任务」;那次的人工验收被整段移交了出去。

按真人完成三个日常任务走查:

| 任务 | 上一版 | 当前主支 |
|---|---|---|
| 把 vision 的链从 A 换成 B | 约 6 击 / 3 滚。且控件只有「在链里 / 不在链里」两态,**没有「换成 B」这个动作**;勾选结果显示在所有供应商分组**下方**,改完要滚下去核对 | 2 击 / 2 滚(换掉一行文本) |
| 改 compress 的 `timeoutMs` | 约 3 击 / 3 滚 —— 当前值显示在任务摘要里,而唯一能改它的输入框在**最后一个区**,值与编辑器隔一整页 | 2 击 / 1–2 滚(同屏) |
| 只想确认 web_extract 现在用哪个模型 | 0 击能读到「链 A → B」,但那一行**不读平台开关与路由层**,可能同时出现「链是 A」与「开关是 native」两句互相矛盾的话;链为空时只显示「(未配置 → 主模型)」,而主模型是谁本页无处可查 | 0–1 击(同屏),同样不回答「主模型是谁」 |

可归纳的机制(均可在归档分支代码里指认):

1. **四层折叠**:宿主导航 → 页内 8 区 → 任务卡 → 选择器内的供应商组。进页面看到的是标题与只读文本,可编辑的东西一个都看不见。
2. **值在一处、编辑器在另一处**:摘要里广告 `timeout 60000ms`,输入框却在页面级「高级」区。
3. **同一事实多处表达**:某任务的链同时出现在概览只读行、任务摘要行与展开后的表单里,只有一个可写 —— 人要自己判断哪一处权威。
4. **一个控件承担两种语义**:同一套「勾选 + 排序」既当有序降级链,又当无序 `nativeRoutes` 白名单,只靠一个只读小标签区分。
5. **无脏状态、无可逆提示**:改完不知道有没有落盘;唯一的撤销是「只在字段有值时出现」的重置按钮。
6. **导航死链**:状态面板的「去配置」按钮指向的组 id 已被改名,点下去毫无反应。
7. **词汇表膨胀**:同一概念在一页里有「降级链」「模型降级链」「降级链(按序尝试)」「链:」「降级策略」五种叫法。

> 仓库内没有任何关于当年为何放弃的记录;以上结论来自 **UI 本身的性质**,不是对动机的猜测。

**结论**:失败不在「想要一个更好的链编辑器」,而在**把一次控件升级做成了一次页面重写**,并用目录式多选去承担「把 A 换成 B」这种单值替换。本设计因此采取与「维护优先」一致的形态:**保留当前控件的心智模型,只补它缺的几件事**。

## 2. 设计目标(五条硬指标,可直接当验收条件)

- **H1 零点击可见且与真实生效一致** —— 打开设置后,任一任务**当前生效的路由**在 0 击 0 展开下可见;平台开关 / 路由层的影响必须体现在同一句话里,不允许「链是 A」与「开关是 native」两句并存。
- **H2 一次连续操作替换** —— 把链从 A 改成 B 在一次连续操作内完成:不跨分区、不跨折叠、不需要「先加新的再删旧的」。
- **H3 改动与结果同屏** —— 链的新顺序在不滚动的情况下与触发控件同时可见。
- **H4 未落盘可见 + 可撤销** —— 有未保存编辑时常驻可见「未保存」状态与一个明确撤销点;切换分组或离开页面不静默丢弃。
- **H5 单一可写点** —— 同一事实整页只有一个可编辑位置;别处出现时必须是同源同刷新的只读镜像。

## 3. 控件设计

链编辑**仍是单个多行文本框**(一行一条 `provider/model`,顺序即时序)。这是满足 H2/H3 最省力的形态,也保证「专家手输」与既有 `settings.yaml` 内容零损失。在它周围补三件事。

### 3.1 行内校验(补 H4 / H2)

- 逐行 trim 后校验形状(按首个 `/` 切分、两侧非空)并按服务端同一规则去重保序(以 provider 与 model 组成的键为准)。
- 非法行**在文本框旁逐行列出**(行号 + 原文 + 原因),而不是像今天那样只在保存被拒后、在页脚显示宿主返回的英文错误串。
- 保存被拒时错误定位到行,不做整段回退。

### 3.2 目录辅助:插入,而不是替换(补 H2,并规避数据丢失)

- 文本框旁一个「从目录插入」入口:按供应商分组的候选列表,点一项 = **在当前行之后插入一行**。
- **既有条目永不因目录而丢失**:目录是「可插入的来源」,不是「可选集合的边界」。目录里没有的条目照常留在文本框里;某行指向的供应商或模型不在当前目录中时,在该行下方给**非阻断提示**(「未在目录中」),但**不改文本**。
- 目录加载失败时(供应商列表调用失败会得到空目录)只禁用「从目录插入」,**绝不改写既有内容**。

> ⚠️ 这是本设计最容易踩的坑:目录是**筛过的**远程结果(只保留 active 的供应商),而设置页保存是**一次性整段提交**。任何「从目录重建链」的实现都会在目录缺项时**静默删掉配置**;而供应商可以由插件贡献,所以「目录里没有」不等于「无效」。

### 3.3 生效路由预览(补 H1 / H5)

文本框下方一行**只读**的「当前生效」摘要,与文本框同屏、无需滚动,取与服务端 `describe()` 同一口径:

- 去重后的链,以及是否追加主模型尾(依 `fallbackToMain` / `visionFallbackToMain` 的当前取值);
- 该任务的平台开关值;当开关为 `native` 时**明确写出「链不生效」**;
- 存在单数 `provider` / `model` 且链非空时,提示「单数被忽略」(今天只在 `/aux status` 里说);
- 链末主模型显示**具体模型 id** —— 今天的概览只写「(未配置 → 主模型)」却不说主模型是谁。

这一行是只读镜像,与文本框同源同刷新,不构成第二个可写点(H5)。

### 3.4 明确的「不做」

- **不做**分区重构、不新增页内折叠层、不改分组 id。
- **不做**目录勾选框式选择器:它把「替换」变成「取消勾 + 勾选 + 到别处核对顺序」,且按构造引入 §3.2 的数据丢失风险。
- **不做**独立排序面板:顺序在文本框里本来就可见(H3)。
- **不做** `nativeRoutes` 选择器与 `/aux models` 能力探测(见 §6)。
- **不写**文档化的分区数:上一版自述「七分区」而界面是 8 张卡。

## 4. 数据流与失败面

| 面 | 今天 | 本设计 |
|---|---|---|
| 写入 | 任务链 setter:文本切行 → ops | **不变,且不改签名** —— 上一版同名不同签名正是它无法与主支合并的原因 |
| 校验时机 | 仅保存时(宿主 validator,错误串在页脚) | 编辑器内即时 + 保存前;服务端 validator 仍是权威 |
| 目录 | 只喂 provider / model / 思考档位三个下拉 | 额外喂「从目录插入」;**不参与既有值的合法性判断** |
| 目录失败 | 目录为空 → 三个下拉变空选项 | 仅禁用「从目录插入」,既有链不受影响 |
| 生效口径 | 仅在 `/aux status` | 编辑器内只读预览 + `/aux status`,**同源** |

## 5. 验收判据

1. **纯函数可测**:抽出 `dsh-aux/src/route-chain-editor.js`,导出
   - `parseChainText(text)` → `{ entries, errors }`(逐行 trim / 形状 / 去重,与服务端同规则);
   - `chainTextFromEntries(entries)` → 文本(与上者往返一致);
   - `catalogHint(entry, catalog)` → 该条目是否在目录中(仅用于提示,不参与校验);
   - `describeEffectiveRoute(chain, facts)` → 预览行的结构化数据。
   单测只测这些纯函数(DOM 不测),沿用仓库既有的「纯函数先例」。
2. **不牵连既有测试**:实测 `tests/` 下没有任何测试引用设置页 DOM,所以改控件不会挂测试;但链解析、设置校验、`aux/llm-call` 字段名与 `/aux status` 文案**都被测试钉住** —— 本设计**刻意不动这四处语义**。
3. **手工走查**(§1 的三个任务):(a) A→B ≤ 3 击且不跨分区;(b) timeoutMs 与其当前值同屏;(c) 「当前生效」一行能单独回答「用哪个模型」,且开关为 native 时明确显示链不生效。
4. **回归**:全量测试、lint、format、docs 索引与脱密闸、`sync-compat --check` 全绿。

## 6. 范围外(另议)

- Phase 4 的其它部分:消息图片画廊角标 —— 独立功能,与链无关。
- `nativeRoutes` 的编辑控件:它同样是多行文本,但消费者语义不同(有序链 vs 白名单)。将来若做,应复用本设计的「文本框 + 行内校验 + 目录插入」,但**必须是另一个控件实例**,不要像上一版那样让一个控件承担两种语义。
- `/aux models` 的图片能力三态标注:需要逐模型探活,是重后端。若做,必须**显式点击才探测**,且绝不把「未知」渲染成看起来像错误的状态。
